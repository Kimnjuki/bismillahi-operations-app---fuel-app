Key Architecture Decisions

  • Single Flat Stack — All 30+ screens (auth + app) are in one NativeStackNavigator. No bottom tabs or drawer.
  • Auth Guard — Conditional initialRouteName: if authenticated → Dashboard, else → PinLogin
  • Token Management — Supabase session tokens stored in Expo SecureStore for persistence
  • Role-Based Rendering — Each screen checks user role to conditionally show/hide features
  • Screen Mode — Screens use a mode prop ('dashboard' | 'add' | 'edit' | 'history') for multi-purpose rendering

⚠️ Key UX Observations & Recommendations
  • 1. No Bottom Tabs — The app uses a single flat stack navigator. All navigation goes through the Dashboard. This is simple but may feel navigation-heavy for frequent actions.
  • 2. Multi-Purpose Screens — Screens like SalesEntryScreen use a mode prop to render different views (dashboard/add/edit/history). This reduces screen count but increases complexity.
  • 3. PIN Authentication — Simple 6-digit PIN login is fast and station-friendly (staff can quickly log in on shared devices).
  • 4. Role-Gated Navigation — Dashboard tiles are filtered by role, so users only see what they can access. No dead-end screens.
  • 5. Session Persistence — Supabase tokens in SecureStore mean users rarely need to re-enter PIN (session auto-refresh).
  • 6. Offline Concern — Types include OfflineOperation and SyncStatus, suggesting planned offline capability, but current implementation relies on live Supabase connection.
  • 7. Print/Export — Reports use expo-print and expo-file-system for PDF generation and sharing.
Data Flow Summary — How Information Moves Through the App
Sales → Stock
When a pump sale is recorded, the system decrements the corresponding fuel tank's stock level. Volume sold is subtracted from available inventory.
Dip Readings → Variance
Physical dip readings are compared against calculated stock (opening + received - sold). Variance alerts trigger when discrepancy exceeds threshold.
Sales → Accounts
Credit sales automatically create entries in Accounts Receivable. Payments against receivables update the remaining balance.
Transfers → Accounts
Fund transfers debit source account and credit destination. Cross-currency transfers apply current exchange rates.
All Data → Reports
Sales, expenses, stock movements, and account transactions feed into report generation with date-range filtering and aggregation.
Events → Notifications
System events (low stock, large transactions, security events) automatically generate notifications displayed in the notification center.
